## 1. المعادلة كما ستُنفذ (BR-32، مع D-35 و D-39)

```
base_price           = سعر الباكيج للفترة في موسم تاريخ الحفلة إن وُجد، وإلا السعر العادي للفترة (BR-30، BR-31)
extra_guests_amount  = max(0, guests − base_guests) × extra_guest_price
items_total          = Σ line_total للبنود المضافة:
                         ثابت داخلي   : unit_price
                         بالعدد داخلي : unit_price × quantity
                         بالفرد داخلي : unit_price × quantity   (quantity = عدد المعازيم وقت التسعير — P4-03)
                         خارجي        : external_fee مرة واحدة للبند (BR-34، D-39)
removal_credits_total = Σ removal_credit للبنود المضمنة المُزالة (BR-33)
subtotal (قبل الخصم)  = base_price + extra_guests_amount + items_total − removal_credits_total
total                = subtotal − discount_amount
شروط: subtotal ≥ 0 (BR-35) · 0 ≤ discount_amount ≤ subtotal (BR-52) ⇒ total ≥ 0 دائمًا
```

- البنود المضمنة غير المُزالة لا تُسعّر (مشمولة في سعر الباكيج — BR-33)، حتى اللي بالفرد ومهما كان عدد المعازيم.
- كل المبالغ أعداد صحيحة بالقرش (`number` آمن، `Number.isSafeInteger`). **لا توجد نسب مئوية في المعادلة**، فلا تقريب داخل المحرك (P4-08).
- ترتيب الفحوص ثابت (P4-01)، والمحرك يرجع أول مخالفة.

## 2. شكل المدخلات والمخرجات (types)

```ts
// src/domain/pricing.ts — دالة نقية: لا قاعدة بيانات، لا وقت حالي، لا تعديل للمدخلات
import type { PackagePrice, PricingType, ServiceCategory, SlotKind } from "./catalog";

/** الخدمة كما في الكتالوج الآن (نسخة من صف services). */
export type PricingService = {
  id: string;
  name: string;
  category: ServiceCategory;
  pricingType: PricingType;
  unitPrice: number; // قروش
  allowExternal: boolean;
  externalFee: number; // قروش
  isActive: boolean;
};

/** خدمة مضمنة في الباكيج (صف package_items مع خدمته). */
export type IncludedService = {
  service: PricingService;
  quantity: number;
  removable: boolean;
  removalCredit: number; // قروش، ثابتة حتى للخدمة بالفرد
};

/** كل ما يحتاجه المحرك من القاعدة؛ يجمعه modules/pricing. */
export type PricingCatalog = {
  package: {
    baseGuests: number;
    extraGuestPrice: number;
    prices: readonly PackagePrice[]; // كل الأسعار، ومنها أسعار المواسم المعطّلة (تُتجاهل)
    included: readonly IncludedService[]; // بترتيب الباكيج
  };
  activeSeasons: readonly { id: string; startDate: string; endDate: string }[];
  services: ReadonlyMap<string, PricingService>; // الخدمات المطلوب إضافتها
};

export type AddedItemRequest = { serviceId: string; quantity: number; isExternal: boolean };

export type QuoteRequest = {
  slotKind: SlotKind;
  eventDate: string; // YYYY-MM-DD = تاريخ starts_at بتوقيت القاهرة (BR-31)
  guests: number; // 1–100000 (P4-06)
  added: readonly AddedItemRequest[];
  removedServiceIds: readonly string[]; // P4-05
  discountAmount: number; // الخصومات المعتمدة فقط (BR-50)، ≥ 0
};

/** بند في التفصيل = صف booking_items في المرحلة 5 (القسم 3). */
export type PriceLine = {
  source: "package" | "added"; // المرحلة 7 تضيف "guest_adjustment"
  serviceId: string;
  name: string;
  category: ServiceCategory;
  pricingType: PricingType;
  unitPrice: number; // اللي القاعة بتحاسب عليه للوحدة: 0 للمضمن وللخارجي (P4-02)
  quantity: number; // بالعدد: الوحدات؛ بالفرد المضاف: المعازيم المغطّين (P4-03)؛ ثابت: 1؛ المضمن: كمية الباكيج
  isExternal: boolean;
  externalFee: number; // يُحسب مرة للبند (D-39)؛ 0 لغير الخارجي
  isRemoved: boolean; // للمضمن المُزال فقط
  removalCredit: number; // منسوخة للمضمن؛ 0 للمضاف
  lineTotal: number; // بإشارة: مضمن 0 · مضمن مُزال −removalCredit · مضاف داخلي حسب النوع · خارجي externalFee
};

export type PriceBreakdown = {
  slotKind: SlotKind;
  eventDate: string;
  guests: number;
  seasonId: string | null; // الموسم اللي سعره اتطبق فعلًا (Q4-01)
  dateSeasonId: string | null; // الموسم النشط اللي فيه التاريخ، للعرض فقط
  basePrice: number;
  baseGuests: number;
  extraGuestPrice: number;
  extraGuests: number; // max(0, guests − baseGuests)
  extraGuestsAmount: number;
  lines: PriceLine[]; // المضمن بترتيب الباكيج، ثم المضاف بترتيب الطلب
  itemsTotal: number; // يشمل رسوم الخارجي (P4-04)
  externalFeesTotal: number; // جزء من itemsTotal، للعرض والتقارير
  removalCreditsTotal: number;
  subtotal: number; // قبل الخصم (BR-52، وأساس العربون كنسبة في المرحلة 6)
  discountAmount: number;
  total: number; // ≥ 0 (BR-35)
};

export type PricingViolation =
  | "guestsInvalid"
  | "discountInvalid"
  | "slotNotPriced" // BR-30، D-56
  | "removedDuplicate"
  | "itemNotIncluded"
  | "itemNotRemovable" // BR-33
  | "addedDuplicate"
  | "serviceUnknown"
  | "serviceInactive"
  | "alreadyIncluded" // Q4-03
  | "quantityInvalid"
  | "externalNotAllowed" // BR-34
  | "amountTooLarge"
  | "negativeTotal" // BR-35
  | "discountExceedsSubtotal"; // BR-52

export type QuoteResult =
  | { ok: true; breakdown: PriceBreakdown }
  | { ok: false; violation: PricingViolation; serviceId?: string };

export function quotePrice(catalog: PricingCatalog, request: QuoteRequest): QuoteResult;

/** المعادلة الوحيدة (BR-32) على أجزاء مخزنة؛ quotePrice يستخدمها، والمراحل 5–8 يعيدوا الحساب بيها. */
export function summarize(parts: {
  basePrice: number;
  extraGuestsAmount: number;
  lines: readonly PriceLine[];
  discountAmount: number;
}): Pick<PriceBreakdown, "itemsTotal" | "externalFeesTotal" | "removalCreditsTotal" | "subtotal" | "total">;
```

**ترتيب الفحوص (P4-01):** المعازيم والخصم ← سعر الفترة (BR-30) ← المُزال (تكرار، مش في الباكيج، مش قابل للإزالة) ← المضاف (تكرار، مش موجود، معطّل، مضمن أصلًا، الكمية، الخارجي) ← الحساب وحد المبلغ ← BR-35 ← BR-52.

**`pricing.quote`** (`src/modules/pricing/`): المدخلات زي API.md مع تعديل P4-05:
`{ spaceId, packageId, slotKind, eventDate, guests, items[{serviceId, quantity, isExternal}], removedServiceIds[], discountAmount? }` ← `PriceBreakdown`.
الخدمة تقرا الباكيج (في المنشأة، على `spaceId`، نشط، ومكانه نشط) وأسعاره وبنوده وخدماتها والمواسم النشطة والخدمات المضافة (كلها بـ `venue_id` المستخدم)، وتنادي `quotePrice`، وتترجم المخالفة لخطأ:

| المخالفة | الكود | القاعدة |
|---|---|---|
| باكيج أو خدمة مش موجودة أو من منشأة تانية، أو الباكيج مش على `spaceId` | `NOT_FOUND` | — |
| الباكيج معطّل | `BUSINESS_RULE_VIOLATION` | قرار جديد (P4-07) |
| مكان الباكيج معطّل | `BUSINESS_RULE_VIOLATION` | BR-06، D-77 |
| `slotNotPriced` | `BUSINESS_RULE_VIOLATION` | BR-30 |
| `itemNotRemovable` | `BUSINESS_RULE_VIOLATION` | BR-33 |
| `externalNotAllowed` | `BUSINESS_RULE_VIOLATION` | BR-34 |
| `negativeTotal` | `BUSINESS_RULE_VIOLATION` | BR-35 |
| `discountExceedsSubtotal` | `BUSINESS_RULE_VIOLATION` | BR-52 |
| `serviceInactive`، `alreadyIncluded` | `BUSINESS_RULE_VIOLATION` | قرار جديد (P4-07، Q4-03) |
| `guestsInvalid`، `discountInvalid`، `quantityInvalid`، `removedDuplicate`، `addedDuplicate`، `itemNotIncluded`، `amountTooLarge` | `VALIDATION_ERROR` (برسالة على الحقل/البند) | — |

العملية للقراءة فقط: لا تكتب أي حاجة ولا سطر في سجل العمليات، وبتقرا الأسعار الحالية في كل مرة (ده اللي هيخلي إعادة التسعير عند التأكيد — D-41 — مجرد نداء تاني).

## 3. التفصيل اللي هيتثبت مع الحجز (المرحلة 5)

`PriceBreakdown` بيتحفظ كما هو، بلا حساب تاني، في الأعمدة الموجودة في DATA_MODEL:

| `bookings` | من التفصيل |
|---|---|
| `season_id` | `seasonId` (Q4-01) |
| `base_price` | `basePrice` |
| `base_guests`، `extra_guest_price` | `baseGuests`، `extraGuestPrice` (لقطة D-35) |
| `extra_guests_amount` | `extraGuestsAmount` |
| `items_total` | `itemsTotal` (شامل رسوم الخارجي — P4-04) |
| `removal_credits_total` | `removalCreditsTotal` |
| `discount_amount` | `discountAmount` |
| `total` | `total` |
| `guests`، `slot_kind`، `package_id` | من الطلب |

| `booking_items` | من `PriceLine` |
|---|---|
| `service_id`، `name`، `category`، `pricing_type` | نسخة وقت التسعير |
| `unit_price`، `quantity` | `unitPrice`، `quantity` (P4-02، P4-03) |
| `source` | `package` / `added` (و `guest_adjustment` في المرحلة 7) |
| `is_removed`، `removal_credit` | `isRemoved`، `removalCredit` |
| `is_external`، `external_fee` | `isExternal`، `externalFee` |
| `line_total` | `lineTotal` (بإشارة) |

**الثوابت اللي الاختبارات بتثبتها على أي تفصيل:**
- `total = basePrice + extraGuestsAmount + Σ lineTotal − discountAmount`
- `Σ lineTotal = itemsTotal − removalCreditsTotal`، و `externalFeesTotal ≤ itemsTotal`
- `total ≥ 0`، وكل المبالغ أعداد صحيحة.
- `summarize(تفصيل مخزن)` يرجّع نفس الإجماليات بالظبط، فأي مرحلة بعد كده تعيد الحساب من الأعمدة المخزنة من غير ما تكرر المعادلة.

## 4. إزاي الشكل ده بيخدم المراحل الجاية

- **التأكيد (BR-21، D-41، المرحلة 6):** نفس `quotePrice` بمدخلات الحجز وبأسعار الكتالوج الحالية، والفرق = مقارنة تفصيلين. (Q4-08: لو الباكيج اتعطّل أو اتغيرت بنوده بين المبدئي والتأكيد.)
- **إضافة بند أو زيادة عدده بعد التأكيد (BR-40، المرحلة 7):** سطر `added` جديد بالسعر الحالي، و `summarize` يعيد الإجمالي.
- **زيادة المعازيم بعد التأكيد (D-35):** المعازيم الجدد بس بالأسعار الحالية كسطور `guest_adjustment` منفصلة. عشان كده سطر "بالفرد" بيتخزن بعدد المعازيم اللي بيغطيهم (P4-03) مش بيتضرب في `guests` الحالي. مثال للتوضيح (تفاصيله في Q4-05): حجز الذهبي 180 معزوم (عدد أساسي 200، سعر الفرد الزيادة المثبت 150 ج) وبوفيه 180 ج للفرد × 180 = 32,400 ج. يزيدوا لـ 230 والأسعار الحالية بقت 160 ج للفرد الزيادة و 200 ج للبوفيه: معازيم زيادة جدد = max(0, 230−200) − max(0, 180−200) = 30 × 160 = 4,800 ج، وبوفيه للخمسين الجدد = 50 × 200 = 10,000 ج، وسطر البوفيه القديم يفضل 180 × 180 ج زي ما هو.
- **تخفيض المعازيم (BR-43):** بالأسعار المثبتة. (Q4-06: لو التخفيض بعد زيادة.)
- **التأجيل (BR-81، المرحلة 8):** `basePrice` بس يتحسب تاني من أسعار الباكيج الحالية لفترة وموسم الموعد الجديد (نفس دالة اختيار السعر في المحرك)، والباقي من الأعمدة المخزنة، و `summarize` يدي الإجمالي الجديد. (Q4-07.)

- الخدمات المضمنة مش بتتسعّر مهما كان عدد المعازيم، حتى اللي بالفرد (BR-33). المعازيم الزيادة بيتحاسبوا بسعر الفرد الزيادة بس.
- قيمة الإزالة مبلغ ثابت حتى للخدمة بالفرد، والإزالة للبند كله، مفيش شيل جزء من الكمية (D-14، BR-33).
- الموسم بتاريخ بداية الحفلة بتوقيت القاهرة (BR-31)، فالمسائي اللي بيعدّي نص الليل موسمه بتاريخ بدايته. وأسعار الموسم المعطّل مش بتتحسب (D-78).
- الخدمة المضمنة اللي اتعطّلت بتفضل مضمنة ومن غير تأثير على السعر (D-80).
- الـ quote بصلاحية `bookings.view` (API.md)، وللقراءة بس.

## أسئلة: غموض وتعارض في قواعد التسعير

> كل سؤال معاه ترشيحي. **Q4-01..Q4-04 لازم تتحسم قبل التنفيذ** لأنها بتغيّر أرقام في الاختبارات. Q4-05..Q4-08 بتخص مراحل جاية، لكن الأفضل تتحسم دلوقتي لأن شكل التفصيل المثبت (المرحلة 5) بيتبني عليها. ولو حبيت تأجلها، الشكل المقترح بيستحمل أي إجابة فيها.

**Q4-01 — `season_id` في اللقطة لما التاريخ في موسم والباكيج ملوش سعر موسم للفترة.**
BR-37 بيحط `season_id` ضمن لقطة السعر، و BR-30 بيقول لو مفيش سعر موسم يتحسب العادي. مثال PR-06: الذهبي نهاري يوم 2027-07-10 (في الصيف)، ومفيش سعر صيف للنهاري، فالسعر 40,000 العادي. يا ترى `season_id` يبقى "الصيف" (موسم التاريخ) ولا فاضي (الموسم اللي سعره اتطبق)؟
**ترشيحي:** فاضي، لأنه جزء من لقطة **السعر**، والعقد مش هيكتب "سعر الصيف" على سعر عادي. والـ quote هيرجّع `dateSeasonId` لوحده عشان الشاشة تقول "التاريخ في موسم الصيف، والباكيج ملوش سعر صيف للفترة دي، فاتحسب العادي".

**Q4-02 — لما BR-35 يتكسر: رفض ولا تصفير؟ وهل فيه حد لقيمة الإزالة؟**
قيمة الإزالة ملهاش حد أعلى (تقرير المرحلة 3، ملاحظة 7)، فممكن الخدمات المُزالة تبقى أكبر من سعر الباكيج. مثال PR-43: الروف 10,000 ج، وشيل الدي جي (6,000) والديكور (5,000) = 11,000، فالإجمالي −1,000.
الخيارات: (أ) رفض برسالة واضحة، والموظف يرجّع خدمة أو المالك يصلّح قيم الإزالة. (ب) الإجمالي يتصفّر والفرق يضيع.
**ترشيحي:** (أ) رفض، لأن BR-35 بيقول "لا يجوز"، والتصفير بيخبّي غلطة في الكتالوج. ومن غير حد إضافي: الشرط على الإجمالي كله بس، فلو العميل ضاف خدمات تغطي الفرق يبقى مقبول (PR-46). لو عايز حد زيادة (مثلًا مجموع الإزالة ميعدّيش سعر الباكيج)، قولّي.

**Q4-03 — إضافة خدمة موجودة أصلًا في الباكيج.**
الوثائق مش بتقول. اقتراحي:
- خدمة **بالعدد** مضمنة: يجوز تتضاف كوحدات زيادة بسعرها (PR-22: مصور تالت)، داخلي أو خارجي (PR-37).
- خدمة **ثابتة أو بالفرد** مضمنة ومش مُزالة: إضافتها تترفض (PR-35: دي جي تاني ملوش معنى).
- خدمة مضمنة **مُزالة**: يجوز تتضاف **كخارجي بس** (PR-34: العميل شال دي جي القاعة وأخد خصمه وجايب دي جي من برا بالرسوم). إضافتها داخلي تترفض (PR-36).
- الخدمة مرة واحدة بس في البنود المضافة؛ لو عايز كمية أكبر يغيّر الكمية (PR-51).
**ترشيحي:** زي ما فوق. محتاج تأكيدك خصوصًا على حالة الدي جي الخارجي بعد الإزالة، لأنها حالة حقيقية في القاعات.

**Q4-04 — البند الخارجي: العميل بيدفع إيه للقاعة؟**
BR-34: "لا يُحتسب سعره كإيراد خدمة، وتُحتسب فقط رسوم الدخول". فهمي إن العميل بيدفع للمتعهد الخارجي بنفسه برا النظام، والقاعة بتحاسبه على رسوم الدخول بس، فالبند الخارجي في الإجمالي = الرسوم بس (PR-23: فرقة خارجية ×2 = 1,500 ج، مش 8,000 + 1,500). الفهم التاني إن القاعة بتحصّل السعر كمان بالنيابة عن المتعهد، بس من غير ما يتحسب إيراد ليها، وده هيغيّر الإجمالي والتقارير.
**ترشيحي:** الفهم الأول (الرسوم بس)، وسعر الخدمة مش هيظهر على البند الخارجي (P4-02).

**Q4-05 — تفاصيل زيادة المعازيم بعد التأكيد (D-35، المرحلة 7).**
فهمي، بالمثال اللي في القسم 4:
- المعازيم الزيادة الجدد = `max(0, الجديد − base_guests المثبت) − max(0, القديم − base_guests المثبت)`، بسعر الفرد الزيادة **الحالي** في الباكيج.
- البنود المضافة بالفرد: كل المعازيم الجدد (حتى لو تحت العدد الأساسي) بسعر الخدمة **الحالي**.
- الخدمات المضمنة بالفرد: مش بتتحاسب للمعازيم الجدد (مشمولة زي ما هي في التسعير الأول).
- لو الباكيج أو الخدمة اتعطّلوا بعد التأكيد: برضه بنستخدم سعرهم الحالي (الصف موجود ومبيتمسحش — D-82).
**ترشيحي:** زي ما فوق. أكّدلي أو صحّح.

**Q4-06 — تخفيض المعازيم بعد زيادة (BR-43 مع D-35).**
مثال: الحجز اتأكد بـ 250 معزوم (سعر الفرد الزيادة المثبت 150 ج)، وبعدين زادوا 50 بالسعر الحالي 180 ج، وبعدين رجعوا قللوا 50. لو التخفيض بالأسعار المثبتة بس، العميل هيترد له 50 × 150 = 7,500 ج ودفع 9,000، فيخسر 1,500 ج على معازيم محضروش.
**ترشيحي:** التخفيض يلغي سطور الزيادة الأحدث الأول بأسعارها (الأحدث فالأقدم)، ولو التخفيض أكبر منها يكمّل بالأسعار المثبتة. كده تخفيض يرجّع بالظبط اللي اتزاد.

**Q4-07 — التأجيل (BR-81، المرحلة 8).**
فهمي إن التأجيل بيغيّر `base_price` بس (و `season_id`)، لأن المعازيم الزيادة والبنود بالفرد بتتحسب تاني "بالأسعار المثبتة" وبنفس العدد، فبتطلع هي هي. سؤالين:
- (أ) ده صح؟ ولا BR-81 قصده حاجة تانية بإعادة حساب المعازيم الزيادة؟
- (ب) لو الباكيج اتعطّل بعد التأكيد، أو ملوش سعر عادي لفترة الموعد الجديد؟
**ترشيحي:** (أ) أيوه، `base_price` و `season_id` بس. (ب) التأجيل لفترة الباكيج ملوش سعر عادي ليها يترفض (D-56)، والباكيج المعطّل يتأجل عادي بأسعاره الحالية، لأن التعطيل بيمنع الجديد بس (نفس روح D-75).

**Q4-08 — إعادة التسعير عند التأكيد (D-41، المرحلتين 5 و 6).**
"يُعاد تسعير الحجز كله بالأسعار الحالية". لو بين الحجز المبدئي والتأكيد: (أ) الباكيج اتعطّل أو اتشال سعر الفترة؟ (ب) خدمة اتضافت للباكيج أو اتشالت منه، أو بند مُزال بقى مش قابل للإزالة؟ (ج) خدمة مضافة اتعطّلت؟
**ترشيحي:** (أ) التأكيد يترفض برسالة، والموظف يختار باكيج تاني. (ب) البنود المضمنة تتنسخ تاني من الباكيج الحالي، والإزالة تفضل للي لسه موجود وقابل للإزالة، والفرق يظهر في شاشة الفرق قبل ما يأكد. (ج) يترفض لحد ما الموظف يشيلها، ولا يتأكد بسعرها الحالي؟ أنا أميل للرفض عشان الموظف يبقى واخد باله.
