| المعيار (ROADMAP) | كيف تحقق |

## 2. ما اتعمل

- **تشفير كلمات المرور (D-64، D-65):** Argon2id عبر `@phi-ag/argon2` (مثبت على 0.6.1، وملف `argon2.wasm` منسوخ في `src/modules/auth/password/vendor` مع الترخيص). نسخة WASM جديدة لكل عملية، واختبار يقطع التشفير في المنتصف ويتحقق أن ما بعده سليم. معاملات OWASP في الإنتاج (19 ميجا، t=2، p=1)، وrehash تلقائي عند الدخول إن تغيرت (P1-09). معاملات خفيفة لـ Worker التطوير فقط، و `cf:build` يرفض الأضعف من OWASP في أي بيئة أخرى.
- **قاعدة البيانات (Migration `0002`):** `users` و `sessions` (hash التوكن فقط — D-61) و `roles` و `role_permissions` و `user_roles` (بلا `venue_id` في جداول الربط والجلسات — D-63) و `audit_logs` مع trigger الإضافة فقط.
- **الدخول والجلسات (`src/modules/auth`):** موبايل موحد أو اسم مستخدم (P1-04، D-52)، تحقق واحد من كلمة المرور في كل محاولة حتى لا يكشف التوقيت وجود الحساب، جلسة 7 أيام تتجدد مع الاستخدام وتُفحص في قاعدة البيانات مع كل طلب (T-17، P1-08)، وتنتهي عند الخروج أو التعطيل أو تغيير كلمة المرور (SEC-04، BR-101).
- **الموظفون والأدوار والملاك (`src/modules/users-rbac`):** BR-100..102 و P1-11 كاملة: المالك يمنح الملكية ويتنازل عن ملكيته فقط، ولا يعيد كلمة مرور مالك آخر ولا يغيّر اسم دخوله؛ غير المالك لا يلمس حساب مالك ولا يمنح صلاحية لا يملكها. الأدوار الافتراضية قابلة للتعديل وتُحذف فقط إن لم يكن عليها موظفون (P1-06).
- **غلاف الـ Server Actions:** `src/server/action-core.ts` (بلا Next.js، تستخدمه الاختبارات بنفس الكود)، وتعريفات العمليات في `src/server/specs/`، وربطها بالكوكي في `src/server/actions/`. الأخطاء بأكواد API.md ورسائل عربية.
- **حماية الصفحات:** طبقة وصول للبيانات `src/server/dal.ts`؛ كل صفحة ودالة بيانات تفحص الجلسة بنفسها، والـ layout طبقة إضافية فقط (P1-08). كل الصفحات المحمية تُعرض لكل طلب (لا prerender).
- **الشاشات (shadcn/ui بدعم RTL):** S-01 الدخول، S-02 تغيير كلمة المرور (إجبارية مع الكلمة المؤقتة)، S-15 الموظفون والأدوار بمصفوفة الصلاحيات، S-16 سجل العمليات بفلاتر وتوقيت القاهرة، وهيكل التطبيق (شريط علوي، تنقل حسب الصلاحيات، قائمة الحساب، خروج) وصفحة رئيسية مؤقتة. أُزيل فحص القاعدة المؤقت من المرحلة 0.
- **حجم الـ Worker:** 7.4 ميجا (1.57 مضغوط)، بعد استبعاد ملفات WASM غير المستخدمة من التتبع في `next.config.ts`.

## 3. التفاصيل التنفيذية المعتمدة (2026-10-17)

1. كلمة المرور الجديدة يجب أن تختلف عن الحالية، وأقصى طول لكلمة المرور 128 حرفًا.
2. كود خطأ إضافي `INTERNAL_ERROR` للأخطاء غير المتوقعة (أُضيف إلى API.md).
3. الموبايل يُقبل بالأرقام العربية، ومن غير الصفر في أوله، وبصيغ +20 و 0020 و 20، ويُوحّد إلى `01XXXXXXXXX`.
4. بعد القفل يبدأ عداد المحاولات من الصفر، والمحاولات أثناء القفل لا تُحتسب (وتُسجل في السجل بسببها).
5. تجديد الجلسة في قاعدة البيانات مرة كل 5 دقائق على الأكثر، والكوكي يُعاد إصداره مرة كل ساعة من المتصفح عبر Server Action.
6. لا تُمنح الملكية لموظف معطّل.
7. ملف `src/server/action.ts` في الخطة قُسّم إلى `action-core.ts` و `specs/` و `actions/` حتى تختبر اختبارات التكامل نفس تعريفات العمليات.
8. الحماية من CSRF معتمدة على فحص Next.js المدمج (مقارنة `Origin` بالـ `Host`)، **ومعها اختبار e2e** يعيد إرسال طلب دخول حقيقي من `Origin` آخر فيُرفض ولا تُنشأ جلسة، بينما نفس الطلب من نفس الموقع ينجح. ملاحظة: Next.js يسمح بطلب **بلا** `Origin` إطلاقًا (لا يرسله إلا طلب مصنوع يدويًا، ولا يحمل كوكي الضحية).
9. مكتبة `cn` (من نفس ناشر shadcn) أُبقيت، وترجمة نص زر إغلاق النوافذ للعربية.

## 4. السكريبتات وطريقة تشغيلها

كلها تقرأ الاتصال من `.env.secrets.local` (`DATABASE_URL`، و `NEON_LOCAL_WSPROXY` للقاعدة المحلية). كلمات المرور تُكتب في خانة مخفية مرتين ولا تُطبع أبدًا. عند تمرير المدخلات عبر pipe تُقرأ سطرًا بسطر.

| الأمر | الوظيفة |
|---|---|
| `npm run db:migrate` | تطبيق الـ Migrations قبل أي تجهيز |
| `npm run setup-venue -- --venue-name "…" --owner-name "…" --owner-login 01XXXXXXXXX` | المنشأة والمالك (كلمة مؤقتة يغيّرها في أول دخول) والأدوار الثلاثة الافتراضية والإعدادات الافتراضية (P1-01). يرفض لو المنشأة موجودة. أي خيار ناقص يُسأل عنه |
| `npm run support:remove-owner -- --login <login> [--yes]` | دعم فني: إزالة الملكية من مالك، بشرط بقاء مالك نشط آخر. يطلب كتابة `yes` للتأكيد ما لم يُمرر `--yes` |
| `npm run support:reset-owner-password -- --login <login> [--yes]` | دعم فني: كلمة مؤقتة لمالك نسي كلمة مروره؛ تنتهي جلساته ويُجبر على التغيير في أول دخول. لغير المالك تُعاد كلمة المرور من شاشة الموظفين |
| `npm run db:seed` | منشأة تجريبية للتطوير (مالك `owner`) |

**التشفير في السكريبتات:** بمعاملات OWASP افتراضيًا. لقاعدة Worker التطوير على الخطة المجانية تُمرر المعاملات الخفيفة للأمر نفسه (ولا تُكتب في أي ملف env يُضمّن في الـ Worker — D-65):

```powershell
$env:APP_ENV="development"; $env:PASSWORD_HASH_MEMORY_KIB="4096"; $env:PASSWORD_HASH_ITERATIONS="1"
npm run setup-venue -- --owner-login 01XXXXXXXXX
Remove-Item Env:APP_ENV, Env:PASSWORD_HASH_MEMORY_KIB, Env:PASSWORD_HASH_ITERATIONS
```
