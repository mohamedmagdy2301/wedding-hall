# المعمارية

## 1. نظرة عامة

Modular Monolith في مشروع Next.js واحد (TypeScript)، منشور على Cloudflare Workers، مع PostgreSQL على Neon وملفات على Cloudflare R2. **نسخة مستقلة لكل منشأة.**

```
المتصفح ──► Next.js (Cloudflare Workers)
              ├─ app/        الشاشات (لا منطق عمل)
              ├─ server/     Server Actions / Route Handlers (تحقق مدخلات + صلاحيات)
              ├─ modules/    طبقة الخدمات ومنطق العمل لكل وحدة
              ├─ domain/     دوال نقية (التسعير، الاسترداد، المواسم، الأقساط)
              └─ db/         المخطط والـ Migrations (Drizzle)
                    │
                    ├──► Neon PostgreSQL
                    └──► Cloudflare R2 (روابط مؤقتة)
```

## 2. التقنيات

| الطبقة | الاختيار | ملاحظات |
|---|---|---|
| الإطار | Next.js (App Router) + TypeScript strict | |
| الواجهة | Tailwind CSS + مكتبة مكونات تدعم RTL | خط عربي، `dir="rtl"` |
| التحقق | Zod | نفس المخططات في الواجهة والسيرفر |
| قاعدة البيانات | PostgreSQL على Neon | مشروع لكل منشأة |
| الوصول | Drizzle ORM + Migrations | مع driver متوافق مع Workers |
| الدخول | تنفيذ داخلي بلا مكتبة دخول خارجية: جدول `sessions` في قاعدة البيانات يخزن hash التوكن فقط، وكوكي `HttpOnly` | D-61 (P1-10)؛ كلمات المرور Argon2id عبر `@phi-ag/argon2` (WASM) بنسخة جديدة لكل عملية (D-64، D-65) |
| الملفات | Cloudflare R2 عبر واجهة S3 | روابط موقعة قصيرة العمر |

> **مهم:** المكتبات وإصداراتها تُحدد وتُتحقق من توافقها مع Cloudflare Workers في المرحلة 0 قبل البناء عليها.

## 3. الوحدات

`auth`, `users-rbac`, `audit`, `settings`, `spaces`, `catalog`, `packages`, `pricing`, `customers`, `bookings`, `payments`, `discounts`, `documents`, `expenses`, `reports`, `printing`.

قواعد:
- الشاشات تستدعي Server Actions فقط؛ لا وصول مباشر لقاعدة البيانات من المكونات.
- كل Server Action: (1) التحقق من الجلسة (2) التحقق من المدخلات بـ Zod (3) فحص الصلاحية (4) استدعاء خدمة الوحدة.
- منطق العمل في `modules/*`، وما يمكن أن يكون دالة نقية يوضع في `domain/*` ويُختبر بلا قاعدة بيانات.
- طبقة الخدمات مستقلة عن Next.js بما يسمح بكشف REST API لاحقًا لتطبيق موبايل.

## 5. الوقت والفلوس

- كل الأوقات `timestamptz`، والتحويل لتوقيت القاهرة في طبقة العرض وفي حسابات التاريخ (الموسم، أيام الإلغاء).
- مكتبة تواريخ تدعم المناطق الزمنية؛ لا اعتماد على توقيت السيرفر.
- `domain/money.ts`: كل المبالغ أعداد صحيحة بالقرش، ودوال تنسيق للعرض فقط.

## 6. التزامن وسلامة البيانات

- العمليات المالية متعددة الخطوات داخل Transaction واحدة، وسجل العمليات يُكتب داخلها.
- قيد منع التعارض في قاعدة البيانات هو الضمان النهائي؛ خطأ القيد يُترجم لرسالة "الموعد محجوز".
- `version` على الحجز لمنع الكتابة فوق تعديل موظف آخر.
- أرقام الحجز والإيصال تُولّد داخل Transaction (sequence أو عداد بقفل صف).

## 7. سجل قرارات المعمارية (ADR)

### ADR-001 نسخة مستقلة لكل منشأة مع مخطط جاهز للتعدد
- **القرار:** كل منشأة لها نشر وقاعدة بيانات منفصلان. مع ذلك كل الجداول تحتوي `venue_id` والمعرفات UUID.
- **السبب:** ميزانية صفر، بداية بعميل واحد، عزل تام بلا تعقيد RLS.
- **التبعات:** التحديثات تُطبق على كل نسخة (Migrations موحدة). الدمج المستقبلي = نقل بيانات بلا تعديل مخطط.

### ADR-002 PostgreSQL بدل MongoDB
- **السبب:** Exclusion Constraint لمنع الحجز المزدوج، Transactions قوية، بيانات علائقية بطبيعتها، JSONB للقطات.

### ADR-003 Next.js كمشروع واحد
- **السبب:** مطوّر واحد مع Claude Code، لغة واحدة، نشر واحد.
- **التبعات:** طبقة خدمات منفصلة لتسهيل كشف API لاحقًا.

### ADR-004 المبالغ بالقرش كأعداد صحيحة
- **السبب:** منع أخطاء التقريب العشري.

### ADR-005 الطباعة وPDF في المتصفح
- **السبب:** حدود المعالجة في الاستضافة المجانية، ودعم الطابعة الحرارية كطابعة نظام عادية.

### ADR-006 المدفوع والمتبقي محسوبان من الدفتر
- **السبب:** مصدر حقيقة واحد؛ استحالة اختلاف الأرقام.

### ADR-007 الحالات الزمنية محسوبة وقت القراءة
- **القرار:** `expired` و `completed` لا تُخزن.
- **السبب:** لا حاجة لمهام مجدولة على السيرفر.

### ADR-008 الاستضافة المجانية (Cloudflare + Neon + R2)
- **السبب:** خطة Vercel المجانية لا تسمح بالاستخدام التجاري؛ Supabase المجاني يوقف المشروع بعد أسبوع خمول ويسمح بمشروعين فقط.
- **المخاطر:** تغير الشروط المجانية؛ حدود وقت المعالجة في Workers. **التخفيف:** تحقق في المرحلة 0، وعدم الارتباط بمزود (Postgres قياسي، واجهة S3 للملفات).
- **التحديث بعد المرحلة 0 (D-57):** عرض الصفحة وتشفير كلمات المرور يتجاوزان حد CPU في Workers المجاني (10 مللي ثانية لكل طلب). التطوير يبقى على المجاني، والإنتاج على Workers Paid (5 دولار شهريًا لحساب واحد يضم كل المنشآت). Neon و R2 كما هما.

## 8. تجهيز نسخة جديدة

سكريبت `scripts/setup-venue.ts` + دليل في README المشروع:
متغيرات البيئة ← migrate ← إنشاء المنشأة والمالك والأدوار الافتراضية والقيم الافتراضية ← نشر.
